# AgentXFlow V2 — Master Implementation Plan

You are upgrading the existing **AgentXFlow** application into a production-grade multi-agent software engineering control plane.

This is an **upgrade, not a rewrite**.

Before modifying anything:

1. Inspect the entire repository.
2. Map all existing Rust modules, React components, database migrations, IPC commands, MCP endpoints, tests and configuration.
3. Preserve working functionality unless this specification explicitly replaces it.
4. Reuse the existing Tauri 2 + Rust + React 19/TypeScript architecture.
5. Do not create parallel duplicate systems.
6. Every new subsystem must connect to the existing Coordinator rather than bypass it.
7. No mock implementations, fake providers, placeholder buttons, dead UI, TODO workflows or visually complete but functionally disconnected components.

The finished product should feel like a **professional engineering operations IDE for autonomous coding agents**, not an AI dashboard.

---

# 1. Product Definition

AgentXFlow is the authoritative execution and governance layer for running multiple AI coding agents against real repositories.

Its responsibility is not merely task management.

It must control:

* collisions

**AgentXFlow remains the source of truth.**

# 4. Modern Protocol Gateway

## MCP

Replace the custom legacy MCP/SSE implementation with a protocol-version-aware MCP gateway.

Primary support:

* MCP `2026-07-28`
* modern Streamable HTTP
* required routing/version headers
* stateless request handling
* modern Tasks extension where appropriate
* `subscriptions/listen` where applicable
* strict Origin validation
* localhost binding by default
* authenticated requests

Keep a clearly isolated compatibility adapter for older MCP clients.

Do **not** make legacy SSE the primary implementation. The current MCP specification has moved to a stateless core and deprecated legacy HTTP+SSE.

## ACP

Add an **ACP Client Runtime**.

ACP is for controlling coding agents; MCP remains the tool/governance interface exposed to them.

ACP Runtime responsibilities:

* discover installed agents
* launch agent subprocesses
* negotiate capabilities
* create/resume sessions
* stream messages/events
* receive permission requests
* cancel/interrupt
* track native session IDs
* collect usage metadata when exposed
* preserve agent-specific configuration/authentication

Use the official ACP Registry as a discovery source rather than manually hardcoding every future coding agent. ACP supports concurrent sessions and bidirectional permission requests over its client/agent model.

Initial targets:

* Codex
* OpenCode
* Claude Agent / Claude Code-compatible ACP integration
* Cline
* Cursor where ACP support is available
* Gemini-compatible agent integrations
* GitHub Copilot-compatible ACP integrations

Keep provider-native adapters only when they provide capabilities ACP cannot expose.

# 8. Never Merge Through the User's Working Copy

This is important.

Create a dedicated hidden integration worktree:

```text
.agentxflow/integration/<project-id>
```

The MergeEngine operates there.

Never blindly checkout `main` in the user's active repository directory.

Before integration:

1. fetch/refresh target state when configured
2. record latest target SHA
3. detect whether task verification is stale
4. simulate merge
5. rebuild combined tree
6. rerun required post-merge verification
7. merge only after all applicable policy gates pass

Support:

* squash
* merge commit
* rebase
* PR-only

Default to **squash** for autonomous task branches unless the project config says otherwise.

Never silently resolve conflicts.

Conflict → `BLOCKED/CONFLICT`.

Allow:

* human resolution
* designated Merge Resolver agent
* abort/retry

# 9. Build a Real Merge Queue

A project can have several individually valid tasks whose combined result is invalid.

Therefore introduce:

```text
MergeQueue
MergeCandidate
IntegrationAttempt
MergeConflict
CombinedVerification
```

Queue operations are serialized per target branch.

When Task A merges:

* Task B's base becomes stale.
* Re-evaluate B.
* Recompute integration diff.
* Re-run required affected checks.

For GitHub repositories, optionally create a PR and respect repository branch protection rather than bypassing it. GitHub supports required reviews, required status checks, linear-history rules and merge queues; AgentXFlow should integrate with these controls rather than pretending they do not exist.

# 12. Scope Engine V2

Keep exclusive leases but stop treating globs as perfect truth.

Implement three layers.

### Layer 1 — Declared scope

Agent proposes expected write paths after analysis.

### Layer 2 — Collision analysis

Detect overlap with other active tasks.

### Layer 3 — Actual mutation audit

Compare real filesystem/Git changes against granted scope.

An agent modifying:

```text
src/auth/**
```

while owning only:

```text
src/payments/**
```

must create a real violation automatically.

The agent should not have to report itself.

Support:

* read scope
* exclusive write scope
* shared/generated scope
* lease expansion requests
* lease TTL
* lease renewals
* manual overrides

Add a **collision risk score**.

Consider not only identical paths but:

* imported modules
* shared config
* package manifests
* database migrations
* generated files
* schemas
* lockfiles

Semantic risk should normally warn rather than hard-block.

# 35. Security Rules

Non-negotiable:

* bind management interfaces to localhost by default
* validate MCP Origin headers
* authenticate protocol requests
* use cryptographically random tokens
* canonicalize workspace paths
* defend against symlink escape
* prevent path traversal
* never execute provider text as commands
* commands and display text must use separate types
* redact obvious secrets from logs
* enforce execution timeout/output limits
* terminate full child process trees
* audit destructive operations
* permission policies must be deterministic

Do not expose unrestricted CORS on a localhost agent-control server.

# 39. Definition of Done

Do not call AgentXFlow V2 finished until all of the following are true:

* multiple real agents can operate simultaneously
* each task executes in isolation
* dependencies prevent incorrect scheduling
* write collisions are detected
* actual mutations are audited
* agents cannot fake verification
* changing code invalidates old verification
* user root checkout never needs to be switched for autonomous merges
* merge queue handles target-branch movement
* conflicts are never silently resolved
* crashed runs are recoverable
* MCP current spec works
* ACP agents can be launched and managed
* unsupported agent features disappear from the UI
* UI updates live without four-second full-state polling
* every task has reproducible proof
* every important action appears in the audit timeline
* the UI works efficiently by keyboard
* the interface contains no decorative glass/gradient/dashboard aesthetic
* no unfinished control is presented as functional
* existing stable functionality still works
* Rust tests, frontend tests and desktop build all pass

The finished product should look and behave like software created by an experienced developer-tools team: **dense, deterministic, restrained, extremely reliable and designed around real engineering workflows.**
